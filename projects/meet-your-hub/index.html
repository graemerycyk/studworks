01 / Hub basics

Meet your hub.

A question, a number, a little red light. Start without moving anything.

By Grae · Development-tested

About these results. These actions worked on a City Hub during earlier development testing. They do not qualify the current release build or other hubs.

On the workbench

Hub
City Hub 88009
Firmware tested
Pybricks 4.0.1
Attachments
No motor or sensor required

Using a Studworks test build? Connect your hub and complete Self-test (no motion) first. If it fails, stop there and share the console output. The app guides you to official Pybricks setup if needed.

First, ask a question

Enter this instruction in Studworks:

Report the battery voltage
  1. Press Make it.
  2. Review the generated plan and code. This should only report battery voltage; it should not include motor movement.
  3. Choose Run it, then read the console.

One of our earlier runs printed:

Battery: 8972 mV

Your number will vary. This is a voltage reading, not a battery percentage or a value to aim for.

Then, give it a signal

This is a separate instruction and run:

Turn the hub light red

Press Make it, review the light-only action, then choose Run it. The hub light should visibly turn red. A “Program finished” message alone is not proof that the light changed.

What this teaches us

Studworks can answer a question about the hub without asking what an unrelated motor is attached to. Hardware questions should be relevant to what you actually asked it to do.

Evidence: Grae’s earlier City Hub testing confirmed battery output and, after a light-control fix, a visible red light. New releases must repeat those checks.
